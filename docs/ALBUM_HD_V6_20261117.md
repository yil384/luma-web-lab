# Album HD v6 production fix (2026-11-17 PT)

## Scope and root causes

The 2026-11-17 v5 published photo book used `photo.thumbnail || photo.src`
for both paper-page prints and animated leaf faces. The generated thumbnail files
are **600 × 600 square**, even for portrait originals such as 1440 × 2160 and
1440 × 1920. Stretching these thumbnails into large portrait frames caused
visible softness and incorrect framing. Independently, nested grid/intrinsic
image sizing could leave a print far below its intended page center.

## Published hotfix on `gh-pages`

- `/assets/PhotoGallery-AlbumHD-20261117-v6.js`: both normal and turning
  pages render `photo.src`, preloading/decoding current and neighboring
  **original-resolution** files. The HD zoom dialog remains unchanged.
- `/assets/memory-album-hd-v6.css`: stable absolute half-page geometry,
  centered fixed-size photo mounts, intrinsic-size isolation and
  `object-fit: contain` / `object-position: center`. Both mobile and
  desktop layouts use the same centering constraint.
- `/index.html`, `/christmas/index.html`, `/album-preview/index.html`:
  import-map entry maps the v5 lazy-import specifier to the new v6 asset.
  The additional v6 CSS is loaded after the existing v5 stylesheet.

Original files under `generated/photos/` were **not** modified. No changes
to the princess V73, fireworks, 3D tree, film, gift page or `/letter/`.

## Verified behavior

Workflow: https://github.com/yil384/luma-web-lab/actions/runs/44207386021

The Chromium regression test checked:
- Both pages use original files with natural width 1440 (rather than 600px
  square thumbnails), before and after turning;
- Print frames are inside their paper pages and center offsets are at most
  2px in the tested desktop viewport and 0px on mobile;
- Left reveal opacity stays zero halfway through the page flip;
- Next, previous, desktop drag, mobile left/right swipe and HD viewer work;
- No browser JavaScript errors; public home, Christmas and letter routes respond.

## Rollback

Revert only the v6 import-map entry and the v6 CSS link in the three HTML
entrypoints on `gh-pages`. Both previous v5 assets are kept in place,
so rollback does not touch any photos or unrelated scenes. The release
metadata and previous commit are recorded at `/album-release-status.json`.

## Source-of-truth warning

`main` still contains a **stale photo-gallery source snapshot**; the
published V73 runtime and published album module are built assets on
`gh-pages`. Do not deploy a naive fresh build of `main` as a replacement
for the live application. When performing the next coordinated source
rebase/release, reconcile the v5 swipe/flicker improvements together with
the v6 original-photo and centering changes first.
